description: 'Undo a scheduled cancellation (cancel_at_period_end=true) with the secret key, so the subscription keeps renewing. ## Overview

Undoes a cancellation scheduled at the end of the period by **your side** — your backend (`cancel_requested_by: "api"`), your dashboard (`"manager"`) or your Stripe dashboard (`null`). The subscription keeps renewing as before.

<Warning>
  **You can't undo the customer's cancellation.** If the customer scheduled it from their management link (`cancel_requested_by: "payer"`), only they can resume it, from that same link; if Payviox did (`"admin"` or `"system"`), contact support. Both return `403`.

  The customer's cancellation is their withdrawal of consent to be charged: renewing anyway would be a charge they didn't authorize, the typical cause of "canceled recurring payment" disputes. For the same reason, if you resume a customer's cancellation directly in your Stripe dashboard, Payviox re-applies the cancellation.
</Warning>

<Note>
  Only a **scheduled** cancellation can be undone. Once a subscription is `canceled` (it reached `current_period_end`, or it was canceled immediately), it can't be resumed: have the customer subscribe again with a new session.
</Note>

## Authentication

This endpoint requires your **Secret API Key** (server-side only). See [Authentication](/api/authentication) for details.

```bash
Authorization: Bearer sk_live_xxxxxxxxxxxx
```

## Path Parameters

<ParamField path="subscription_id" type="string" required>
  The Payviox subscription ID (`psub_...`).
</ParamField>

## Response

The updated [Subscription object](/api/endpoints/get-subscription#the-subscription-object), with `cancel_at_period_end: false` and `cancellation_reason: null`. If no cancellation was scheduled, it returns `200` without changing anything.

## Example Requests

<CodeGroup>

```bash cURL
curl https://api.payviox.com/subscriptions/psub_8fKx2LmQp4ZrT7vW1nYc3aBd/resume \
  -H "Authorization: Bearer sk_live_xxxxxxxxxxxx" \
  -X POST
```

```javascript Node.js
const response = await fetch(
  'https://api.payviox.com/subscriptions/psub_8fKx2LmQp4ZrT7vW1nYc3aBd/resume',
  {
    method: 'POST',
    headers: { Authorization: `Bearer ${process.env.PAYVIOX_SECRET_KEY}` },
  }
);

const subscription = await response.json();
console.log(subscription.cancel_at_period_end); // false
```

```python Python
import os
import requests

response = requests.post(
    'https://api.payviox.com/subscriptions/psub_8fKx2LmQp4ZrT7vW1nYc3aBd/resume',
    headers={'Authorization': f"Bearer {os.environ['PAYVIOX_SECRET_KEY']}"}
)

print(response.json()['cancel_at_period_end'])  # False
```

## Error Responses

<AccordionGroup>
  <Accordion title="401 -- Unauthorized">
    The API key is missing or invalid. This endpoint only accepts your **Secret API Key**.
  </Accordion>

  <Accordion title="403 -- Cancellation scheduled by the customer or Payviox">
    `cancel_requested_by` is `payer` (only the customer can resume, from their management link) or `admin`/`system` (contact support).
  </Accordion>

  <Accordion title="404 -- Subscription not found">
    No subscription with this ID belongs to your business (`subscription_not_found`).
  </Accordion>

  <Accordion title="409 -- Already canceled">
    The subscription has already ended and can't be resumed. A `409` with `The subscription changed meanwhile. Try again.` means it was modified during your request: retry.
  </Accordion>

  <Accordion title="502 -- Provider refused">
    Stripe refused the change. Nothing was changed on Payviox's side: contact [support@payviox.com](mailto:support@payviox.com).
  </Accordion>

  <Accordion title="503 -- Provider unreachable">
    Stripe couldn't be reached, or Stripe isn't configured on your account anymore. Nothing was changed: retry later.
  </Accordion>
</AccordionGroup>
